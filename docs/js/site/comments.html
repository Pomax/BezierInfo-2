    • Pomax Thursday, January 14, 2021 2:26 PM

      Given n points, we can construct a unique (n-1)<sup>th</sup> order polynomial function y=f(x), such that y=f(x) will pass through each point. And that phrasing should already suggest why that doesn't apply here: Bezier curves are not polynomial functions of the form y=f(x), they are instead multi-dimensional parametric functions, with each dimension using a polynomial basis function of the same order and of the same variable.

      If I arrange four points in a slightly rotated "rectangle", then the unique 3rd order polynomial y=f(x) that passes through all those points will look like a standard symmetrical third order function, and if I arrange them as an axis aligned "rectangle", then there is no polynomial that will fit them because we would need y=f(x) to yield two different values of y for one value of x. While there are functions that do this (the most obvious being the square root function), polynomials cannot.

      And you might think "but hang on, each dimension is just a polynomial, which has to pass through four points, so that's a unique polynomial right there", but this isn't actually true... We can find a unique solution for y=f(x) because given coordinates of the form (x,y), there are unknowns: for each point, both the input (x) and the output (y) are prescribed.

      However, for a 2D Bezier curve, we have (y,x) = f(t), and while we know the output values (x and y), we do not know anything about the associated input values (t). So unlike regular polynomials, where we're working with two unknowns, and we can find the unique solution because we have values for both of those unknowns, for 2D Bezier curves we're working with three unknowns, while only having values for two of those. By definition, this gives us infinitely many solutions. Many of which will be wildly inappropriate and completely useless, I might add =D

      So, to find decent curves through points, we must first decide on what the missing values should be (this is called "clamping" a variable). Once we do, we can find a unique solution. And that's what the section on curve fitting describes: we have to decide how to "clamp" t (i.e. we're turning our (x,y) points into (t,x,y) points) so that we can then find "the" solution.

            • Pomax Monday, July 4, 2016 8:05 PM

              Wikipedia has this covered fairly well: Bezier curves are just Bezier curves, a multidimensions parametric function that uses Bernstein basis functions, with each point on the curve defined by all coefficients in the basis functions, controlled by all control points - if you move one control point, every "point" on the curve moves.

              B-splines, on the other hand, are piece-wise interpolations where each part of the curve, even with lots of control points, is only controlled by a few local points, called knots; a bit like a poly-Bezier. Move on control point, you only change a small portion of the total curve. In fact, B-splines are a generalised form of Bezier curves in this respect: a B-spline for a curve with N points that uses an Nth order basis function is equivalent to the Bezier curve for those points. However, we can form a B-spline of a lower order.

              NURBS take this one step further and are in turn a generalised form of B-splines, where in addition to "being a B-spline", every knot is assigned its own weight, so that in addition to controlling the curvature complexity through the basis function, we now also control it by mixing in a weight function for each point.

              I don't have any immediate plans to extend the article with B-Spline and NURBS, although if I ever do, it'll be in that order.
